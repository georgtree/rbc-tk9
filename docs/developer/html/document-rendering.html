Document renderer primitives¶

The SVG, PDF and PostScript renderers consume mapped display geometry through Rbc_RenderOps. They do not perform axis mapping, decimation, page delivery or graph lifetime management. rbcRenderExport.c selects the backend and prepares its style context; rbcRenderExportInt.h describes the shared state. See Rendering architecture and contracts, Export orchestration and document ownership and Document renderer C reference.

Context lifetime and state¶

Each constructor allocates a short-lived renderer context borrowing the Rbc_ExportContext. A PDF context requires an initialized PDF builder; a PostScript context requires the legacy token in backendData. SVG writes to the current export buffer. None of these constructors begins or completes a document. The export and graph must outlive all contexts that reference them.

Stroke construction copies SVG/PDF colors and dash values, clamps width to at least one, and caches cap/join settings. Fill and symbol constructors make shallow style copies: referenced colors, bitmaps and tiles remain borrowed. Fill/symbol contexts also borrow the graph for display and window information. Changing a resource or destroying its owner during drawing is not supported merely because the style structure was copied.

PostScript stroke/symbol setup emits state immediately. SVG/PDF generally read cached style when drawing. In particular, PostScript’s DashesProc and DrawSymbolProc are dictionary definitions shared by the document. Complete one configured batch before another context changes them; gsave does not isolate these definitions. This differs from PDF’s local graphics-state scopes.

Use Rbc_RenderEnd rather than calling the backend destructor directly. It unwinds explicit clips tracked by the common dispatcher, then frees the context. It does not finish the document, release builder resources or balance a separate plot-begin scope. Plot begin/end must remain paired by the caller.

Geometry and painter order¶

Primitives receive pixels with downward-increasing Y. The enclosing PDF page matrix converts pixels to points and reverses Y. PostScript page setup supplies the equivalent coordinate system. Applying this conversion again in a component would misplace geometry and scale stroke widths twice.

PDF paths use decimal coordinates and cubic Bezier pieces of at most 90 degrees for elliptical arcs. The common arc dispatcher supplies finite, normalized, nonzero extents. Full ellipses close; partial chords close between endpoints; pieslices add the center before closing. PostScript constructs a scaled unit circle and restores the transformation matrix while retaining the path, so stroke widths and dashes stay in display units.

PDF independent segments are emitted one at a time, each with its own solid background pass followed by dashed foreground when configured. This ordering matters at intersections. Connected polylines retain one connected path per pass. PostScript splits connected paths at the legacy 1500-component limit and restarts at the shared endpoint. Replacing either strategy with a different batching policy is a rendering change, not only an optimization.

Fills, patterns and resource ownership¶

PDF prepares fill resources before constructing the shape path. Pattern construction can emit temporary paths, so reversing this order can consume the shape intended for painting. Polygon and arc fills use the even-odd rule; rectangle and geometric-symbol fills use their respective ordinary fill paths.

PdfPattern temporarily redirects the export buffer to a local DString, builds a colored tiling pattern, restores the original buffer and registers the pattern with the PDF builder. The builder owns copied bytes; the renderer caches only its resource ID. Stipples become horizontal bitmap runs over an optional background. Tiles use photo pixels when available, otherwise the shared Tk image capture helper. Tile placement accounts for the graph’s offsets within its containing toplevel; pattern matrices also include page scale and Y reversal.

Rbc_RenderSetFillTile borrows the new tile and invalidates the cached pattern ID for SVG/PDF. Existing document resources remain owned by the export. Other style mutation is not a general cache-invalidation API: construct another fill context when changing the style.

PDF fill opacity below one uses a nonstroking alpha resource. Nonpositive opacity suppresses filling. PostScript retains its legacy foreground/background and stipple behavior; it does not gain alpha or image-tile support from sharing the interface. Its rectangle and polygon paths also retain different fallback rules. See PostScript output and drawing state before attempting to unify them.

Photo conversion respects Tk pitch, pixel size and channel offsets. A distinct alpha channel contributes an SMask only if at least one pixel is nonopaque. Resource registration copies bytes, so neither the photo block nor the capture must remain alive after registration. The image-use matrix corrects raster Y orientation independently of the enclosing page matrix.

The shared non-photo capture helper renders the image over black and white. It estimates alpha from the largest per-channel difference, then unpremultiplies the black capture. It releases its pixmap, GC and second capture and returns one owned color image. This approximates conventional alpha compositing; it cannot recover arbitrary custom image drawing semantics. Deleted or zero-sized images are omitted, whereas pixmap/capture failures record export errors.

Window export captures the current mapped window; it does not create a hidden widget layout or a clipping container. The component/export policy determines whether to request capture. PostScript deliberately omits generic non-photo Tk images and uses its legacy photo/window emitters for the other cases.

Text, borders and symbols¶

PDF text obtains an owned layout, resolves document font characters and adjusts zero-width Tk measurements only when the fallback glyph has a positive advance. It recomputes justification before anchoring and rotating the layout. Shadow is painted before normal/active foreground. Glyph placement combines Tk prefix advances with fallback corrections; this emitter is not an independent shaping engine. See Text layout and document fonts for font selection and embedding and PDF resource builder and serialization for finalization of reserved font resources.

PDF relief borders use Tk’s lazily initialized border colors and paint solid rectangles plus a polygon. Groove/ridge compose two smaller reliefs. Clearing a PDF rectangle paints opaque white; it does not restore transparency. These operations do not acquire ownership of the Tk border or colors.

Symbol batches preserve legacy per-shape size corrections and rounding. Geometric symbols fill before outlining, skinny plus/cross symbols only stroke, and bitmap symbols preserve aspect ratio. PDF reads bitmap/mask XImages once per batch and rejects mismatched mask dimensions when the mask is used. Bar legend samples use unscaled squares with the fill context. PostScript instead configures prolog macros; its validity requirements and fallback behavior must be reviewed separately from PDF’s checks.

Errors and callback boundaries¶

Most emitters return void. A zero resource ID or false fill result is not a complete export status: empty/disabled content can be omitted normally, while other failures record an error on the export. Partial output must be discarded when the enclosing export fails. Temporary content buffers must be restored even when resource creation fails; renderer destruction alone cannot repair an unbalanced graphics scope or finish a partially emitted document.

These functions run on the Tk interpreter’s thread and borrow live Tk resources. Ordinary append-only geometry does not evaluate Tcl scripts, but image display procedures and legacy token helpers can cross external callback boundaries. The non-photo raster helper checks image validity at entry but does not retain or revalidate all borrowed resources across arbitrary custom image display callbacks. Do not infer protection against such destructive reentry from the export command’s graph guard. This documentation patch does not change that behavior or the public C API.
