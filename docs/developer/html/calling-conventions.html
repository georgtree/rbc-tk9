C calling conventions¶

These are shared interpretation rules, not substitutes for a function’s own contract. A specific parameter, return or lifetime description takes precedence. The same page is a Doxygen reference target, so source comments can link here with @ref rbc_calling_conventions.

page Shared C argument and lifetime conventions

Interpreter arguments¶

A Tcl_Interp pointer named interp is normally borrowed for the duration of the call. It identifies the interpreter used for results, diagnostics and interpreter-owned objects; passing it does not transfer ownership. Do not assume NULL is accepted unless the function says so. TCL_ERROR normally leaves a diagnostic, but legacy helpers with different behavior document it. Preservation keeps a record allocated; it does not prevent interpreter deletion or make interpreter services valid after deletion.

Tcl command arguments¶

In a registered object command, objc counts borrowed objv entries and objv[0] names the command. Treat the array as read-only. RBC dispatchers may pass a shifted argument vector to a private handler; that handler’s contract defines its positions and arity. Do not retain an entry beyond its guaranteed lifetime without taking a Tcl reference, or mutate shared Tcl objects without following Tcl copy-on-write rules. Conversions that evaluate expressions can run Tcl.

Callback client data¶

ClientData is an untyped pointer, not an ownership annotation. Each callback must specify its concrete target (for example a graph, vector, or stack-local status flag), who owns it, and when it remains valid. Registration does not itself imply a reference count or preservation guarantee.

Results and output pointers¶

An output pointer is not necessarily an ownership transfer. Each function describes whether a returned object is borrowed or owned, which release operation applies, and whether outputs remain unchanged, are cleared, or may be partly initialized on failure. A Tcl status alone does not promise rollback.

Reentry and object lifetime¶

Run interpreter-owned operations in the owning thread. Tcl evaluation, variable traces, notifications and custom storage destructors can invoke client code. Preserving a record does not preserve its old buffers or prevent renaming, remapping, locking or destruction. Revalidate the specific state needed after a callback; documented local checks are not a universal guarantee.

Writing parameter contracts¶

Use @param[in], @param[out] and @param[in,out] for function-specific arguments. State units, accepted ranges, NULL handling, ownership and the state of output arguments on failure. For conventional interpreter and command-vector arguments, link the common description and document only exceptions locally. Always describe the concrete meaning of clientData; it has no universal object type. See C documentation conventions for examples and link syntax.
