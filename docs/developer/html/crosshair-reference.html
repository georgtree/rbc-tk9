Crosshair C reference

These private helpers borrow graph state. See Crosshair state and presentation before changing erase/update/present ordering.

Lifecycle and background changes

int Rbc_CreateCrosshairs(Graph *graphPtr)

Create the graph-owned named crosshair component.

Initializes resource name crosshairs and class Crosshairs, then prepares derived geometry and XOR drawing state. Returns TCL_OK on success; failure destroys the partial record and leaves crosshairs NULL with a diagnostic.

Parameters:

  • graphPtr – [inout] Graph with no existing crosshair record and a live Tk configuration context.

void Rbc_ConfigureCrosshairs(Graph *graphPtr)

Refresh crosshair drawing state after a graph background change.

Reuses validated option values and requests GC reconstruction through ConfigureCrosshairs. That helper erases old pixels before replacing the GC and redraws eligible requested hairs. This void interface discards the conversion status and does not schedule a full graph redraw.

Parameters:

  • graphPtr – [inout] Live graph; a NULL crosshair record is a no-op.

void Rbc_DestroyCrosshairs(Graph *graphPtr)

Release crosshair options and native resources during graph teardown.

Detaches the record before freeing Tk options, option table, private GC and allocation. Does not erase an overlay on a continuing window; callers own visual transitions before teardown.

Parameters:

  • graphPtr – [inout] Owning graph with a live Tk cleanup context; NULL crosshairs is allowed.

Direct overlay control

void Rbc_EnableCrosshairs(Graph *graphPtr)

Restore XOR crosshairs when requested and drawable on screen.

Honors hidden state and draws only when the window is mapped, hairs are not already visible, and the hotspot is inside the plot. Does not change -hide.

Parameters:

  • graphPtr – Live graph with initialized crosshairs and current segments.

void Rbc_DisableCrosshairs(Graph *graphPtr)

Temporarily erase currently visible XOR crosshairs.

When not hidden, erases on a mapped window using the current GC and segments. Does not change -hide. Call before overwriting geometry in direct redraws.

Parameters:

static void MoveCrosshairs(Graph *graphPtr, Crosshairs *chPtr, const Point2D *hotSpotPtr)

Batch Windows position-only XOR erasure and drawing.

Requires unchanged drawing style/GC and a live graph/window. Computes new segments from hotSpotPtr and current graph bounds; compares both visibility and endpoints to avoid redrawing identical geometry. Submits up to four old/new segments in one renderer call, preserving a single native drawing batch.

Always updates hotspot, segments and visible, including when unmapped or hidden. Does not alter hidden or allocate a replacement GC. Only appropriate for position-only configuration; style changes must erase with the old GC. No Tcl callbacks or event processing may intervene in this transition.

Parameters:

  • graphPtr – [in] Borrowed live graph with current plot bounds.

  • chPtr – [inout] Prepared crosshairs with unchanged style/GC; hotspot, segments and visible state are replaced.

  • hotSpotPtr – [in] Borrowed new hotspot in widget pixels; copied, not retained.
