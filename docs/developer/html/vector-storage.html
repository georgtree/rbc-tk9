Vector C API and storage primitives¶

This chapter connects the installed vector API to its implementation in rbcVector.c. The public contracts are in Vector storage public C reference; private allocation and lifecycle helpers are in Vector storage private C reference. See Vector ownership and notifications for the ownership policy table and observer protocol, and Vector indexed edits and rearrangement for the newer Tcl command commit paths.

Public versus private entry points¶

generic/rbc.decls defines the public stub slots. The creation, lookup, resize/reset, data access, change-reporting and read-only APIs reviewed here are public entries. Rbc_CreateVector2 and names beginning with Rbc_VectorNew, Rbc_VectorCreate, Rbc_VectorChangeLength and Rbc_VectorDuplicate are private implementation helpers; similar spelling does not make them interchangeable with installed APIs.

Include rbc.h and initialize the appropriate RBC stubs interface as described in Package loading and stubs; see Header structure for header boundaries. Do not copy private record layouts or add declarations for private helpers to an external extension. The observer declarations discussed in Vector client C reference remain a separate case: declarations in a header do not by themselves establish public stub availability.

Registry and creation¶

Rbc_VectorGetInterpData lazily creates interpreter-associated registry, math-function and special-index tables. It does not install Tcl commands. A private Rbc_VectorNew allocates an unregistered empty record with no numeric storage, idle notification policy, invalid extrema and an empty observer chain. A caller using it as a temporary releases it with Rbc_VectorFree.

Rbc_VectorCreate adds or reuses the registered identity, configures its instance command and optionally maps an array. It qualifies creation names in the current namespace, requires existing vectors to be writable and type compatible, and rejects commands belonging to another object. Its #auto path checks both registry and command collisions. Missing namespaces are errors; this helper does not create them.

The public creation functions are create-or-reuse, despite old comments claiming that an existing name was always an error. Their positive initial size resizes the vector; zero does not clear an existing vector. New records start empty. Added values are zero-filled, while the retained prefix survives resizing. The optional output pointer is borrowed, not a new ownership reference.

Rbc_CreateVector selects real type. Rbc_CreateVectorWithType accepts real or complex type and normally requests a same-named Tcl command. Automatic array mapping is requested for real names without (; complex vectors and names containing parentheses do not get that automatic mapping. Explicit command and array names belong to the private Rbc_CreateVector2 interface.

Creation is not a transaction. Mapping can run Tcl traces before the initial positive-size resize, and a later allocation failure does not undo all earlier registration or existing-object changes. The low-level creation path can also delete/recreate an existing instance command. The revised command output helper instead retains existing commands/mappings and maps new outputs after filling them; that stronger ordering must not be inferred for public C creation.

Lookup and borrowed views¶

Rbc_VectorExists2 tests a literal registry name. It does not accept a client ID or evaluate range syntax. Rbc_GetVector accepts a vector reference, including a selected range, and refreshes invalid extrema before returning. Selection changes the original record’s shared first/last fields; the returned pointer is not an independent slice and its public length remains the full vector length. See Vector names, indices and mapped arrays for evaluating index expressions.

Modification counter, not a boolean or pending-idle flag

An empty vector can also have NULL storage. Query type and length separately. Raw pointers are not retained across storage replacement, destruction or Tcl callbacks. The dirty counter advances through internal change scheduling, including when ordinary notifications are disabled; an unreported native write does not advance it. It is not an object-lifetime token.

Resizing, resetting and copying¶

Rbc_VectorChangeLength selects capacity by doubling from DEF_ARRAY_SIZE until the requested length fits, with overflow checks. Equal capacity reuses the allocation; otherwise it copies the retained prefix into new storage. It zeros added values and sets the shared selection to 0..length-1. Shrinking may release excess capacity, and zero length releases storage entirely.

That private primitive invalidates extrema but does not flush the mapped cache or notify clients. The public Rbc_ResizeVector adds cache flushing and a full update. Its failure path replaces the detailed resize message with a generic message; it is not a name-based lookup API and requires a live vector pointer.

The two public reset functions share ResetVectorStorage after checking type. Reset validates nonnegative length/capacity, length <= capacity and byte-count overflow. NULL data or zero capacity produces empty static storage after validation. TCL_VOLATILE allocates capacity-sized storage and copies only used values; unused capacity is not initialized by this path. Other policies borrow or adopt the supplied pointer. See Vector ownership and notifications for release ownership.

A same-address reset still changes the ownership contract. Volatile input is copied even when its address equals the old vector allocation; that old allocation is then released under its previous policy. This does not extend the lifetime of a borrowed pointer into the old allocation. Unlike resize, reset does not reset the private shared selection. Successful reset publishes a full change, but is not an appropriate substitute for announcing an in-place write.

Rbc_VectorDuplicate is a private resize/copy primitive, not the revised Tcl dup handler. It copies selected values and offset into an existing same-type destination without creating it or notifying clients. memmove handles buffer overlap, including a same-object selected subrange. Copying finishes before old storage is released or callbacks can invalidate the source.

Protection, publication and destruction¶

Rbc_VectorCheckWritable checks a live record’s protection flag and reports RBC VECTOR READONLY. It does not validate arbitrary or destroyed pointers. Check before a native write, and recheck after callbacks that might change protection. Rbc_VectorSetReadOnly normalizes its argument to a boolean and sends no value-change notification. Lifetime operations remain separate.

Rbc_VectorChanged and Rbc_VectorChangedRange publish already-completed in-place writes without changing length or ownership. The ranged form uses inclusive storage indices independent of the external offset. Neither function checks writability; notification cannot retroactively authorize a write.

Rbc_FreeVector delegates to private destruction, which retains the record and interpreter through callbacks and ignores recursive destruction. It deletes the command and mapping, removes registration, cancels pending idle delivery, and sends synchronous DESTROY with length zero. Registration has been removed before observer DESTROY callbacks, allowing those observers to create a new identity with the same name. Command deletion/unmapping happen earlier and have their own callback boundaries. Remaining clients and owned numeric storage are released before deferred record reclamation. Preservation of a record does not keep its name, storage or logical identity usable after destruction.

Callback boundaries and ownership commits¶

These changes preserve public C signatures, installed headers and stub slots. Resize, reset, creation and publication retain the participating record and interpreter across callbacks. Retention protects the record itself; destruction still invalidates its logical identity and borrowed storage. A same-named replacement is never substituted for that identity.

Storage replacement installs complete metadata before releasing old custom storage. Custom release procedures can inspect the committed state. Private resize and duplication recheck identity, protection, storage and selection after release, returning an error if it is no longer safe for their callers to continue writing. The committed change and callback effects are not rolled back.

Reset has a different ownership boundary: once it accepts the supplied storage, it returns success even if a subsequent callback destroys the vector. An error before that commit leaves ownership with the caller. Returning an error after adopting a buffer could make a caller free that buffer twice. Success therefore means that RBC accepted the ownership contract, not that the borrowed vector pointer remains usable after callbacks.

Publication preserves interpreter result state across cache traces and observers. It skips notification if flushing destroys the identity. Public resize may return success after a publication callback destroys the vector; callers must track lifetime separately before reusing borrowed pointers.

Creation writes its optional output pointer only on success and rejects callbacks that destroy its identity. Initial-size failure removes a newly created identity if it remains alive. Existing-object changes and arbitrary callback effects are not rolled back. Command-deletion traces that install a replacement command are rejected without overwriting that command.

These protections require a valid pointer at entry. They cannot validate a pointer already freed by an earlier call, intercept native pointer writes, or make cross-thread access safe.

Post-callback checks and publication¶

A retained vector record can be logically destroyed while its memory remains available. VectorAlive checks that distinction and interpreter deletion; it is not a guard for arbitrary pointers. CheckResizedVector additionally checks writability, numeric storage identity, length, capacity and full-vector selection after a callback. These checks protect subsequent writes using saved bounds. They do not detect every mutation: a callback can change values while leaving the same storage layout in place.

Storage release and change publication have separate roles. The completed replacement storage contract must be installed before ReleaseVectorStorage invokes a custom free callback. Static storage is left alone and dynamic storage uses the allocator directly. Saving the Tcl interpreter state around custom release preserves the outer result, but the caller still owns lifetime protection and post-callback validity checks.

PublishVectorChange preserves the original vector and interpreter, optionally flushes mapped-array cache, and rechecks logical liveness before notifying observers. It does not look up the name again: a callback-created vector with the same name is a different object. Interpreter result restoration does not roll back mutations made by callbacks.

Observer snapshots and interval scope¶

Notification snapshots and preserves client IDs rather than linked-list nodes. A callback may unlink itself or another client, add observers, or destroy the vector. Delivery checks that each ID is still valid and attached to the original server before calling it. New observers do not join the current snapshot, and vector destruction stops the remaining update callbacks. All retained IDs are released even after early termination.

The pending interval is copied locally and cleared before callbacks start. Each client temporarily receives that event’s full/ranged metadata. Nested immediate notifications save and restore this per-client metadata, so querying the interval after nested delivery returns the outer event’s interval again. The vector’s accumulating pending state and a client’s currently delivered interval are therefore distinct records.

ScheduleVectorUpdate merges inclusive ranged intervals; a full update supersedes them. Immediate policy delivers before the scheduling call returns, while idle policy keeps at most one queued notification. Disabled notification still increments the dirty generation. This helper does not maintain extrema: callers invalidate or update the range before scheduling observers.

Incremental extrema maintenance¶

For a real vector, an exact changed interval can preserve the cached global range without scanning unaffected data. If either cached extremum index was overwritten, a full recomputation is required even when another equal value might exist elsewhere. Invalid intervals or inconsistent cache state likewise fall back to recomputation.

Otherwise only changed finite values are scanned. Equal extrema retain the lowest index, and the no-finite-values state uses NaN bounds with negative indices. A successful incremental update commits both values and indices. Invalidation instead marks the cache dirty and stores those sentinel values; it does not itself notify observers. Correctness depends on callers reporting all modified indices, not merely the subset that changed visibly on a graph.

Variable-trace errors use Tcl object results¶

VectorTraceError returns a retained Tcl object through the historical char * trace callback signature. RBC registers these traces with TCL_TRACE_RESULT_OBJECT; Tcl therefore treats the return value as an object, not a C string. Removing that registration flag or reusing the helper for a string-result trace would violate the ownership and representation contract.

Names, namespaces and access surfaces¶

Vector identity belongs to the interpreter-local registry. Literal registry lookup does not inspect Tcl command aliases or parse an index suffix. An explicit namespace restricts the search to that namespace; an unqualified name uses the requested current/global search flags. Returned vector pointers are borrowed, not retained client IDs, and lookup does not change the vector’s index selection. Higher-level parsers decide when parentheses describe a literal name or a range.

The name helpers have different contracts. BuildQualifiedName prefixes the current namespace unless the input already starts with a global qualifier; it does not check namespace existence. ParseQualifiedName finds the final separator and resolves an existing namespace, returning a tail pointer into the original string. Without a separator it reports no namespace, leaving search policy to the caller. GetQualifiedName joins a known namespace and a tail. Both construction helpers initialize caller-owned DStrings; their returned pointers expire when those strings are changed or freed.

The instance command and mapped array are access surfaces, not the registry record itself. DeleteCommand clears the vector’s token and disables its instance deletion callback before deleting by token. This avoids deleting an unrelated same-name command in the caller namespace, but does not suppress all user command traces. The surrounding operation must still retain resources and check whether callbacks destroyed or changed them.

UnmapVariable detaches the old array name before unsetting the variable. User unset traces can then destroy or remap the vector without the helper later reading the old vector fields. The captured name remains owned locally until unset completes. Neither helper is a complete vector destructor, and neither makes arbitrary continuation after callback activity safe.

Creation parsers and bounded index strings¶

The creation-option parsers report consumed argument counts: one on success, minus one on missing or invalid input. Boolean and size parsers write their output only after conversion. A successfully parsed Tcl_Size still needs the caller’s vector length and allocation checks. The type parser accepts exact real/complex names and records whether the choice was explicit; it does not change an existing vector’s type.

String-size conversion owns a temporary Tcl object. Bounded index parsing similarly copies a half-open character span, allowing a range endpoint to be parsed without modifying or NUL-terminating the caller’s input buffer. It then delegates external index offsets, special indices and flags to the ordinary index parser. The copied string is temporary; returned numeric indices have no ownership relationship with it.
