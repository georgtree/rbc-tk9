PostScript output and drawing state

See Document renderer primitives for shared context ownership and the PDF/PostScript primitive contracts, including graphics-state and capture boundaries.

PostScript output is independent of Cairo. rbcGrPs.c owns page setup and command delivery, rbcRenderPostscript.c implements renderer primitives, and rbcPs.c supplies the private output token and legacy drawing helpers. library/rbcGraph.pro supplies executable PostScript procedures used by both layers. See Export orchestration and document ownership for callback protection, geometry restoration, file delivery and the Windows EPS preview wrapper.

Token ownership

Rbc_GetPsToken() allocates a token with an empty DString, NULL font/color map names and color output selected. Its interpreter and Tk window are borrowed. The command assigns mapping variable names from its PostScript configuration; the token does not own those strings. Rbc_ReleasePsToken() frees the DString and token, but none of these borrowed objects.

During rbcGraphPostscript.GraphToPostScript(), the shared export context’s buffer points to the token’s DString and backendData points to the token. Renderer contexts borrow that export context and token. Destroy renderer contexts before ending the enclosing export; releasing shared export state does not release the alternate DString. The command releases the PostScript token separately.

The returned output pointer is a temporary view, not a detached document. Appending can invalidate it. Scratch storage is separate from the DString but is reused by formatting and prolog reads. Neither storage is safe for an independent, interleaved writer. Raw append helpers accept C strings; they are not a binary document API.

Prolog and page setup

Page setup emits EPS metadata and includes rbcGraph.pro from the directory named by rbc::library. An installed Tcl library is therefore a runtime export dependency, even though primitives are implemented in C. The included prolog defines such operations as Fill and symbol procedures; primitive output is not a self-contained PostScript document.

Setup converts display pixels to points using screen resolution, reverses the vertical direction, then applies page origin, orientation and scale. Drawing primitives continue to receive display coordinates. A successful traversal appends showpage and the closing graphics/dictionary scope. Creation-date metadata means byte equality across separately timed exports is not a reliable geometry test.

Prolog loading can leave partial output after an error. It reports lookup, open and read failures, closes the channel, and does not propagate close failure. The enclosing export must discard failed output rather than treat the buffer as a completed document.

Graphics-state boundaries

Plot begin establishes the background and opens a saved clipping scope; plot end restores it. Nested rectangular clips also pair gsave and grestore. Preserve this nesting when adding track-local or component clips.

Dash-background strokes use DashesProc; symbol batches use DrawSymbolProc. These procedures are redefined in the document dictionary. A graphics-state save does not make dictionary definitions local. Emit a batch’s definition and uses together; do not interleave another batch that redefines the same procedure.

Elliptical arcs temporarily transform a unit circle. The backend saves and restores the current transformation matrix on the operand stack, retaining the constructed path. It restores display units before stroking or filling so line widths, dashes and stipples are not stretched with the ellipse. Polyline output is split at 1500 path components, restarting at the shared endpoint. Changes to this batching must preserve connected geometry and stroke behavior.

Legacy primitive contracts

The helpers in rbcPs.c append to the existing token; they do not construct a page, write a file or own a renderer context. Their coordinates are already mapped. They rely on the enclosing transformation and clip, and generally do not validate geometry or save/restore graphics state. Components should still use renderer operations rather than add direct calls to these legacy helpers.

Foreground and background conversion use the upper eight bits of each XColor component. The default prolog maps foreground to black and background to white in monochrome mode, or converts to grey in greyscale mode. An optional Tcl color-array entry instead supplies raw PostScript code and bypasses these operators. A lookup may execute a read trace, so this is a callback boundary, not just a color-table read. The enclosing export must protect borrowed lifetimes; the void color helpers do not expose lookup errors or undo output. rbcPsPrimitives.Rbc_ClearBackgroundToPostScript() merely selects white: it clears no pixels.

Line attributes have their own compatibility rules: zero-width lines become one user unit, CapNotLast maps to butt, and dash phase is always zero. The combined attribute helper also replaces DashesProc with an empty procedure. Callers that need a dash-background pass must define it after that setup.

Relief rectangles

rbcPsPrimitives.Rbc_Draw3DRectangleToPostScript() draws only border bands. It initializes Tk’s light-border GC before querying shadow colors, so export need not wait for a screen draw. Bottom and right strips are rectangles; the top/left band is a polygon. Raised and sunken relief exchange the light and dark sides. Groove and ridge recurse with half-width bands and complementary relief. Odd border widths retain the existing integer split and inset rules.

The helper omits borders if either dimension is smaller than twice the border width. Inputs must keep that multiplication and inset arithmetic representable; this is not an arbitrary-size geometry validator. Colors and the final polygon path remain selected after emission. rbcPsPrimitives.Rbc_Fill3DRectangleToPostScript() first fills the whole background, then invokes the border helper: skipping the border does not skip the fill. Border colors use background conversion, preserving the monochrome policy rather than treating relief bands as foreground strokes.

Text and fill limitations

Rbc_AppendPostScriptString() emits literal-string contents, not the enclosing parentheses. It decodes Tcl UTF text, escapes delimiters and controls, and encodes ISO-8859-1 characters with octal escapes where needed. Characters outside that repertoire become spaces. This path does not use the SVG/PDF embedded-font mechanism described in Text layout and document fonts.

The renderer’s fill path supports foreground, optional background and stipple operations. It does not apply the fill opacity used by other backends. Document these format differences rather than assuming that a shared renderer operation guarantees identical capabilities in every exporter.

Raster ownership and encoding

The legacy raster helpers do not use SVG/PDF font or image resources. They append inline hex data and depend on the current PostScript environment. Their inputs and temporary resources have distinct ownership:

rbcPsRaster.Rbc_ColorImageToPsData() traverses rows from bottom to top. RGB output emits red, green and blue bytes. Its one-component branch emits the bitwise complement of the red channel; it does not itself calculate luminance. The outer serializer first calls Rbc_ColorImageToGreyscale() for noncolor output, modifying the borrowed image. Both monochrome and greyscale token modes use this same raster branch; they do not threshold each pixel into a one-bit mask. Alpha is ignored, so transparent samples are neither omitted nor composited with a background.

Data lines hold at most sixty hex digits, prefixed by the supplied string and a space. Wrapping continues across image rows; the final partial line also gets a newline. The return value counts emitted data lines, not success/failure. Unsupported component counts append nothing and return zero. rbcPsRaster.ByteToHex() writes exactly two uppercase digits without a NUL terminator.

The image program defines tmpStr as a row-sized input buffer and places an eight-bit image or colorimage under a translated/scaled graphics state. The negative vertical image matrix and bottom-to-top sample traversal are existing encoding behavior. grestore restores transforms and drawing state, but does not undo the dictionary definition of tmpStr.

The row-buffer byte count is formatted as size_t, preserving counts above INT_MAX without a varargs type mismatch. This is serialization of the count, not a guarantee that a PostScript interpreter accepts arbitrarily large strings.

Bitmap acquisition and payloads

Bitmap payloads are angle-bracket hex strings. Each row is packed separately, with the first pixel in the high bit and unused tail bits zero. This differs from the continuous byte stream of a color image. rbcPsRaster.ReverseBits() implements the bit-order conversion; wrapping counts complete output bytes.

Legacy font selection

rbcPsText.Rbc_FontToPostScript() chooses a name and point size for the prolog’s SetFont. It does not embed font programs or resolve fallback glyphs per character. Font selection follows this order:

Source

Behavior

Configured font-map array

Lookup by Tk_NameOfFont. A found entry ends the search, even when its list or size is malformed.

Recognized family prefix

A font-map entry’s first element replaces the name. Its size is used only for an exactly two-element list with a valid integer second element. A one-element mapping retains the initial size twelve; it does not inherit the Tk font size. An empty list retains the Tk name. An invalid list or size may leave an interpreter diagnostic, but the helper still emits SetFont and returns void. Mapped names are inserted as PostScript name syntax without escaping or validation, so callers must supply usable PostScript names.

For core X11 fonts, property mapping requires all three named properties. Adobe families remain unchanged. Other foundries strip a leading itc plus space and use an exact alias match, falling back to Helvetica. A typeface suffix is taken from the full name only when it starts with the original family; spaces and dashes are removed before appending that suffix. The returned mapped name lives in a caller-owned DString, allowing the X font to be freed before emission. Atom names themselves remain borrowed from Tk.

The alias table is a compatibility heuristic, not an inventory of installed PostScript fonts. A prefix match in the Tk-family path and an exact match in the X11-property path are intentionally documented as different operations. SVG/PDF font embedding uses the separate machinery in Text layout and document fonts.

Text transforms and fragment widths

rbcPsText.Rbc_TextToPostScript() builds a borrowed-string layout, computes the rotated box, translates the requested anchor to that box’s center, and emits BeginText. The prolog saves graphics state, translates to the center, rotates by the negative angle, then translates to the unrotated layout origin. Font selection and any shadow pass follow; the main pass selects active or normal foreground. EndText restores graphics state. No native disabled/emphasis relief pass is implemented here, and the style’s angle is not rewritten.

Each nonempty fragment emits its escaped literal string, measured screen width and baseline through DrawAdjText. That prolog procedure adjusts character spacing to match the requested width, flips the vertical scale and uses ashow. Empty fragments contribute layout spacing but emit no string, avoiding division by zero in the prolog’s length-based adjustment. The string encoding remains ISO-8859-1 with unsupported characters replaced by spaces; width adjustment does not recover glyphs lost during that conversion.

Font and color mapping can execute Tcl variable traces while the layout borrows its original string. The helper does not preserve the enclosing graph, style, font or string itself; callers own that lifetime protection. Temporary layouts, font-description objects, split-list arrays and mapped-name DStrings are released by their respective helpers.

Fragment baselines and shadow offsets are added in Tcl_WideInt and emitted without narrowing to int. Normal coordinates retain the same decimal output; large sums no longer overflow signed int. The bounding-box calculation normalizes the angle remainder into [0, 360), so equivalent negative and positive rotations use the same anchor position. BeginText still receives the original angle and the style is unchanged. Callers must keep input angles and rounded dimensions within the conversion helpers’ ranges.

Graph options and export lifetime

rbcGrPs.c owns the graph-facing postscript component, whose option resource name is postscript and class is Postscript. Creation uses the shared option proxy, validates derived values and destroys the partial record on failure. Destruction detaches the record first, releases Tk options and the option table, then frees the allocation. It must run while the graph’s Tk configuration context is still usable.

Configuration has two layers: Tk option objects and derived numeric fields. Dimensions, padding, color mode and preview format are converted into locals before committing any derived field. If conversion fails after Tk_SetOptions, rbcGraphPostscript.SetPostScriptOptions() restores the saved options and error state. Successful callers release the saved options. Queries use Tk_GetOptionValue and Tk_GetOptionInfo without rendering.

Options supplied to postscript output are persistent settings. They remain installed even if a later prolog, rendering or file operation fails. This is separate from restoration of screen geometry. rbcGraphPostscript.GraphToPostScript() pairs Rbc_ExportBeginGraph() with Rbc_ExportEndGraph() on both success and failure. For a surviving window, EndGraph resets dimensions to the live window, marks mapping work and schedules redraw. It does not immediately restore all mapped arrays or revert requested PostScript dimensions. The enclosing widget command owns callback lifetime protection; these helpers do not acquire it independently.

Page layout and preview paths

rbcGraphPostscript.ComputeBoundingBox() applies positive requested plot dimensions, exchanges the oriented extents for landscape, and computes a common scale from the available paper area after padding. Maxpect permits enlargement as well as reduction. Centered placement replaces the padding origin when the page is larger than the scaled plot. Wide arithmetic and positive-int clamping precede storage of the inclusive bounds. Layout failure propagates before document traversal.

rbcGraphPostscript.PostScriptPreamble() converts pixels to points using screen pixel and millimeter dimensions, emits escaped metadata and optional preview, loads rbcGraph.pro, and emits footer and coordinate transforms. Metadata includes the current time; byte-for-byte output comparisons must account for that field. Reading rbc_version can execute variable traces. Font/color mapping during traversal can also execute traces; the graph must remain protected throughout export.

EPSI uses a native graph snapshot, converts it to grayscale, rotates it for landscape and encodes eight-bit preview rows. Resizing to a thumbnail is enabled only by THUMBNAIL_PREVIEW; the ordinary path uses the current export layout size. Failure to capture an image omits the preview without a separate error. Drawing invalidation is checked before capture and again by the preamble. This snapshot path is distinct from the vector document traversal.

The preview parser accepts nonempty prefixes, with EPSI on all platforms and WMF on Windows. TIFF and its prefixes are rejected on every build, including those defining HAVE_TIFF_H, because no TIFF preview encoder exists. Windows binary packaging is selected explicitly for WMF. String output returns the PostScript payload without that binary wrapper.

Delivery and ownership

rbcGraphPostscript.OutputOp() owns the PostScript token and staging DString, while the token borrows the component’s font/color mapping names. Rendering and any binary preview assembly finish before opening the destination through Tcl’s filesystem API. Binary channel translation preserves document bytes. Short writes and close failures propagate, and cleanup preserves an earlier error instead of replacing it with a close diagnostic. Successful file output has an empty Tcl result.

This ordering avoids truncating a destination on a rendering failure, but is not an atomic replacement protocol: an open, write or close failure can leave an empty or partial destination. The temporary token and DString are released on every rbcGraphPostscript.OutputOp() exit after their creation. Component options outlive them.

Maintenance checks

When changing this layer, check ordinary and track graphs, nested clipping, solid and dashed strokes, symbol batches, stipple fills, arcs and text with parentheses or backslashes. Check failures with a missing prolog separately from successful output. Keep page framing and delivery in rbcGrPs.c; component code should request renderer operations rather than assemble a new PostScript document.

Parameter and return-value boundaries

The token helpers operate on one caller-owned document buffer. The pointer from Rbc_PostScriptFromToken() is borrowed and can move on the next append; Rbc_ScratchBufferFromToken() is separate reusable storage overwritten by formatting and prolog reads. Neither accessor returns an independent copy. Do not feed either buffer back into an operation that overwrites or relocates it before consuming the input.

Rbc_AppendToPostScript() takes NUL-terminated strings and a pointer-valued NULL sentinel. Rbc_AppendPostScriptString() instead accepts an explicit UTF byte count ending on a character boundary and escapes literal contents. It is still a text converter, not a binary append or general Unicode font encoder. Its caller supplies the parentheses.

The command helpers receive the full widget command: index two is the PostScript operation. Only rbcGraphPostscript.SetPostScriptOptions() receives a sliced option/value array. Passing the full array to that helper would attempt to interpret the widget and subcommand names as options.

Variable-trace cancellation

The preamble’s reads of rbc_version and rbc::library can invoke user read traces. Keeping the graph record allocated does not keep its Tk window alive. rbcGraphPostscript.PostScriptPreamble() therefore checks graph validity after the version read and after successful prolog loading, before continuing to use widget or component state.

If a trace destroys the graph, output returns an error and the export cleanup still runs. File destinations are opened only after successful assembly, so this cancellation leaves an existing destination untouched. Recreating a widget with the same pathname does not revive the original graph record. These checks protect against destruction; they do not make arbitrary reentrant changes to export options transactional.
