Track ownership and layout

A trackgraph is one graph widget with a linked list of named plot regions. Tracks are not child windows or independent graph instances. rbcGrTrack.c owns track records, configuration, ordering and stack layout. Axis, element, marker, grid and legend implementations retain their ordinary module owners.

Records and dependencies

The graph owns the track list. Each record owns its name and axis-pointer array, holds references to its assigned Y axes, and owns optional local grid and legend components. An axis has a back-pointer to its track. Elements and markers refer to tracks but remain graph-managed objects; deleting a track through the command interface does not implicitly delete its data components.

Track names are case-sensitive and lookup scans the list. OrderTracks() relinks the same records, preserving component and binding identities. A borrowed RbcTrack * remains valid across reordering, but not deletion or teardown. The all track binding target uses the address of the graph’s list field, not the current first track. See Binding dispatch and picking for dispatch and repicking.

Configuration and axis ownership

InitTrackOptions() reads creation defaults using the named Track option-database component, with the resource-name conversion used by older components. Temporary TrackDefaults fields retain Tcl objects rather than immediately converting axis names or dimensions. Explicit options replace database defaults before validation; the effective option list goes through ConfigureTrack().

ConfigureTrack() stages scalar values and a replacement axis array. It rejects duplicate axes, incompatible classes or margins, axes owned by another track, and axes used by graph-wide markers. Removing an axis is rejected when an existing track element, local grid or track marker still uses it. New axis references are acquired before old ones are released, so an axis retained in both lists survives replacement.

On success, the caller synchronizes the Y-axis display chain. SyncTrackAxes() rebuilds that chain in track order and axis-list order, updates on-screen flags, marks RESET_WORLD and schedules redraw. This is logical Y-axis ownership: inversion changes physical orientation, not the axis class.

Sizing and visible bounds

Tracks share the graph’s other plot dimension. Normal layout divides the vertical range; inverted layout divides the horizontal range. Historical height and minHeight field names mean size along this stacking direction.

Fitted layout subtracts inter-track gaps from the available range. If the sum of minima fits, each track receives its minimum plus a weighted share of the remainder. If minima exceed the available space, their proportions determine the reduced sizes. Positive bounded weights are enforced by configuration. Fitted gaps shrink with the available range, up to 12 pixels.

Scrolling layout uses max(height, minHeight) for each track and 12-pixel gaps. Its content extent may exceed the viewport. Each track stores full world bounds and their clamped visible bounds. Components must use world bounds for mapping and visible bounds for clipping; using visible height as the data scale would move data when scrolling. See Axes, mapping and track viewports for paired Rbc_EnterTrack()/Rbc_LeaveTrack() scopes and Scrolling and viewport policy for the separate stack-offset and local data-axis scroll operations.

SetTrackSash() in fitted mode adjusts the adjacent pair’s weights while preserving their sum. If the pair has no room beyond its minima, the operation does nothing. In scrolling layout the sash changes the first track’s requested height instead. Both paths invalidate layout and schedule redraw; they do not directly draw into the window.

Local components and dispatch

A NULL local grid means inheritance from the graph grid. A local grid keeps its own configuration and mapped segment caches. Local legends use track geometry without contributing outer graph margins. Track bar mode -1 means inheritance from the graph. See Grid mapping and inheritance, Legend ownership and layout and Bar elements for component-specific behavior.

Nested component commands adapt their argument vector for the existing grid or legend dispatcher. The adapter allocates an array and one retained, list-valued command prefix; all other entries borrow the original objects. Use the paired free helper, not a loop decrementing every entry. This keeps ordinary component command handling and diagnostics reusable.

Deletion and teardown

DeleteTracks() validates every requested name and dependency before removing anything. Duplicate names are harmless. Tracks with elements or markers must first have those components moved or deleted. Each removed track releases its bindings, local grid and legend, axis references, pointer array and name. The remaining axis chain is then synchronized for redraw.

Graph teardown follows a different entry point: after dependent components are disposed of, Rbc_DestroyTracks() releases the entire list before axes are destroyed. It does not revalidate user-facing dependencies or schedule redraw. Keep binding tables, the Tk window and other component cleanup resources alive until their owners have been released; see Graph lifecycle and redisplay.

Maintenance checks

Changes to ownership should cover failed configuration without partial commits, axis retention across replacement, complete and invalid permutations, duplicate delete requests, dependency rejection, and graph teardown. Layout changes need normal and inverted orientations, undersized fitted regions, scrolling, resizing and resized export. Reordering must also repick a stationary pointer after layout, without requiring a new motion event.

Axis-chain synchronization and option queries

Committing a track change and updating the displayed axis chain are separate steps. SyncTrackAxes() removes old chain links and clears their on-screen flags, then rebuilds the Y-axis chain from track order and each track’s configured axis order. Axis objects and retained references survive this relinking. The helper requests a world reset and deferred redraw; it does not perform layout itself.

TrackOptionIndex() resolves names against shared specifications. func:TrackOptionInfo builds the five-field :c:description using current values from TrackOption(), which reads live track fields. Consequently :c:sash-adjusted heights and weights appear in later queries rather than stale creation-time Tcl objects. Axis queries :c:construct names in configured order, and a negative bar mode is reported as inherit. These result objects do not own :c:the referenced axes.

FreeTrack() is a resource destructor, not a list operation. Its caller must first validate dependencies and detach the record. It removes bindings and local grid/legend resources, clears axis-to-track ownership, releases axis references, and frees the axis array, name and record. Reordering instead relinks existing records and does not use this destructor.

Sash geometry and scroll fractions

TrackStart() and TrackEnd() supply sash calculations with unclipped world bounds along the physical stacking dimension: top/bottom normally and left/right when inverted. Visible clipped bounds would produce incorrect sizes for tracks partially outside the viewport. The helper parameter named y therefore represents the stacking coordinate, not necessarily a vertical screen position.

In fitted mode, dragging redistributes the adjacent tracks’ weight sum after subtracting their minimum sizes. When no space above those minima remains, the operation is a no-op. The computed weights must stay positive and within the configuration limits before either is stored. In scrolling mode, dragging changes only the preceding track’s requested height; it does not preserve the pair’s combined physical size. Both paths schedule remapping rather than drawing immediately, and pixel rounding can shift the resulting boundary by one pixel.

TrackViewOp() manages track-list scrolling, separate from every data-axis viewport. TrackViewFractions() computes fractions using the visible physical range and an extent no smaller than that range. A query ensures layout is current. Moveto addresses the total extent; a page advances 90 percent of the visible range and a unit advances 20 pixels. Nonfinite requests or computed offsets are rejected before updating the stored offset. Fitted layout always stores a zero offset for successful scrolling requests.

Notification lifetime boundary

NotifyTrackScrollbar() runs after drawing and suppresses exports. It caches changed fractions before evaluating a duplicated command prefix, so a callback that triggers another draw without changing fractions does not notify forever. An empty prefix is a no-op after caching. Prefix syntax has already been validated by configuration; command existence is checked only by evaluation.

The command receives first/last fractions and runs globally with the graph and interpreter preserved. Errors are reported as background exceptions and the previous interpreter state is restored. Preservation protects storage lifetime, not continued widget validity: the callback may destroy the graph. No graph fields are read after callback evaluation in this helper. The surrounding notification service similarly repicks stationary pointers, checks that the widget survived binding callbacks, then invokes scrollbar notification.

Dispatch and notification contracts

Rbc_ConfigureTrackGraph() validates the widget-level track options; func:Rbc_TrackOp dispatches the full :c:widget command under its enclosing lifetime protection. Rbc_CreateTrackComponentArgs() adapts nested grid and :c:legend arguments without copying every Tcl object. Its retained command prefix and array must be released with :c:Rbc_FreeTrackComponentArgs() before the borrowed arguments expire.

Rbc_FindTrack() returns an unretained identity: ordering does not invalidate it, but deletion does. Rbc_NotifyTrackView() may execute bindings and scrollbar callbacks that delete the widget; its internal preservation does not guarantee that the graph remains usable after return. Rbc_DestroyTracks() is teardown, after dependent elements and markers have gone and before axes are freed. Rbc_DrawTrackSeparators() uses current world bounds and limits strokes to visible gaps.
