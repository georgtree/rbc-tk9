Renderer C reference¶

These declarations are private implementation interfaces, not installed APIs. Callers must obey the capabilities of the constructor they selected; generic operation names do not imply that every context implements them.

Component-facing interface¶

Private graph rendering interface used by mapped components.

Geometry is in mapped widget/display coordinates, not axis data coordinates. Contexts and their borrowed resources must stay on the owning Tk thread. A constructor defines the supported operations; unsupported callbacks are not automatic fallbacks. Check nullable constructor results before drawing. End each allocated context exactly once with Rbc_RenderEnd(). Document tokens, drawables, GCs and component-owned resources remain borrowed.

This header is not installed and does not define the public vector ABI. See license.terms for redistribution terms.

RBC_RENDER_ARROW_POINTS¶

Native-only screen details borrow the exact GC, preserving XOR and dash semantics.

Arrow points include the repeated closing vertex. Text backgrounds consume four outline points and add the anchor before integer conversion.

RBC_RENDER_BITMAP_OUTLINE_POINTS¶

Mapped bitmap presentation borrows the marker’s private GCs and resources.

A rotated opaque background is already clipped/mapped by the component; mask then refers to the bitmap itself, as in the legacy drawing path.

Enums

enum Rbc_RenderArcStyle¶

Ellipse in mapped display coordinates.

Zero degrees points right; positive sweeps turn counterclockwise. |extent| >= 360 is one closed ellipse, without a radial seam. The renderer constructs the complete path under the context’s clip; callers must not clip/flatten it first. Geometry transforms do not scale stroke width, dashes, or fill patterns. This is a private C interface.

Rbc_RenderContext *Rbc_RenderBeginScreenClip(Graph*, Drawable, GC copyGC, int useDC)¶

Screen clip scopes preserve absolute coordinates, shared GCs and bitmap masks.

copyGC is borrowed, or NULL to create a private copy GC. useDC keeps the existing Windows symbol path; other scopes use reusable scratch pixmaps. Only ClipBegin/ClipEnd/ClipDrawable/End are supported by this context. Fetch ClipDrawable after each push; None means the clip is empty or failed. End balances any outstanding pushes. Native/Cairo drawing into the returned drawable is committed to its parent on ClipEnd.

void Rbc_RenderEnd(Rbc_RenderContext *ctx)¶

Unwind remaining clip scopes and destroy an allocated context.

The context is invalid after this call. Backend-owned temporary resources are released; borrowed graph, document, GC and image resources are not. PlotBegin/PlotEnd scopes must already be balanced. Stack-based one-shot screen adapters manage their own lifetime and must not be passed here.

Backend dispatch¶

struct Rbc_RenderContext¶

Prefix embedded first in every allocated backend context.

Constructors initialize the entire allocation. Rbc_RenderEnd() unwinds clips and calls ops->end, which releases backend state and the allocation. Borrowed graph/document resources must remain alive until that completes.

struct Rbc_RenderOps¶

Geometry dispatch and lifetime operations for one context family.

Populate only supported operations. Dispatch generally calls them directly; a caller using the wrong context family can dereference a NULL callback. Clip callbacks implement backend state; the common layer owns clipDepth.

The callback declarations below are included directly from the header. This preserves their exact C syntax across Doxygen/Breathe versions that otherwise place function-pointer member names after the pointer declarator.
